# LazyTerm

A lightweight, keyboard-driven workspace for remote hosts. LazyTerm aims to bring the useful parts of a Termius-style workflow to a local-first TUI: SSH host management, terminal access, SFTP, tunnels, and command snippets.

The project is at an early stage. The Hosts view reads aliases from `~/.ssh/config`, organizes them by local tags, and opens them with the system OpenSSH client. Basic creation, editing, and deletion are available for LazyTerm-managed hosts. Files has a local-first dual-pane browser with an embedded SFTP directory view, per-host connection reuse, recursive transfers, transfer history, and confirmed file mutations. Tunnels support Local, Remote, and Dynamic/SOCKS forwards with process supervision. Snippets are organized into Packages, can run against a Host or tagged Host group with bounded concurrency, and show per-host output and status. Runtime inspects local or remote TCP listeners through the same Host catalog. Projects organizes local commands by base directory, supervises their processes, and links their listening ports back from Runtime.

## Requirements

- Rust stable
- macOS currently targeted; OpenSSH is expected at `/usr/bin/ssh`

## Run

```sh
cargo run
```

The top tab bar switches between Hosts, Files, Tunnels, Snippets, Runtime, Projects, and Credentials. Use the visible tab number (`1`-`7`) to jump directly, `Tab` / `Shift+Tab` or `Ctrl+Left` / `Ctrl+Right` to cycle, and backtick (`` ` ``) to toggle back to the previous tab. Press `,` to open the global Settings panel; press `Esc` or `Tab` there to return. Plain arrow keys navigate within Hosts, not between tabs. Returning to Hosts preserves its group, filter, and selection.

Metadata saves lock the configuration and compare it with the snapshot read by that instance. A changed or removed file blocks saving instead of overwriting another instance's changes; close older instances and press `r` in Hosts to reload before retrying. Each save retains up to 30 previous versions in `hosts.json.backups/` alongside `hosts.json`. `hosts.json.writes.jsonl` records the time, PID, code location, outcome and collection counts without passwords, commands or credential references. Versions predating this protection can still overwrite the file and should be closed before using the new build.

Only one TUI can run against the same LazyTerm data directory. A second launch exits before terminal initialization or configuration loading and reports the existing owner's PID and terminal when available. The OS releases the instance lock when the process exits, including after a crash; a remaining `tui.instance.lock` file does not block restarting and should not be deleted manually. SSH askpass helpers and persistent Project runners use their own lifecycles and can run alongside the TUI.

Settings currently stores a Dark/Light theme choice, an English/Chinese language choice, visibility for each workspace tab (including Credentials), and configuration export. Settings remains accessible through `,` so hidden tabs can be restored. Configuration export opens a native save dialog with `lazyterm-export.json` as the suggested name and includes the LazyTerm metadata, the discovered Host catalog, the root OpenSSH config text, and readable `Include` files; saved password fields and private key files are excluded. The separate credential export asks for a confirmation password, opens a native save dialog, and writes an age-encrypted `.age` file containing saved manager passwords and Project Web Link passwords from either supported storage location. Private keys are not included.

In the **Credentials** tab (default shortcut `7` / `F7`), `a` creates a password in the system credential store, `g` generates an Ed25519 key pair in a new private directory, and `i` registers an existing OpenSSH private key with its matching `.pub` file. Existing `~/.ssh` keys with a matching private file and `.pub` file are also discovered whenever the tab opens; `r` rescans. Discovery reads public-key files for fingerprints and checks that the paired private file exists, but never reads private-key contents. Third-party OS credential entries are not enumerated; LazyTerm-managed and Project Web Link Keychain references are shown with their source. Project Web Link credentials remain managed from Projects. Generated keys have no passphrase; the form states this before generation. Existing directories and key files are never overwritten. `e` edits a password record (blank preserves its saved secret) or an SSH key's display name; the key file path is read-only and shown in the details. `p` copies a password or public key, and `d` removes a record after confirmation. `Enter` does not associate a credential with a Host; Host actions are started from Hosts. Removing an SSH key record leaves its files and SSH config entries intact. Secret-store operations run in workers and a failed metadata save preserves the previous credential. The tab supports normal workspace switching, Settings and `q` to quit.

Credential details show a single **Related Hosts** list for both passwords and SSH keys. SSH key matches from configuration and default key discovery are combined in this list; they do not verify the remote server's authorized keys or prove successful authentication.

To replace a saved Host password, select the Host and press `p`: the Keychain password editor opens with the password field focused. Enter a replacement and press Enter to save; blank preserves the current password. Press `x` in Hosts to delete its saved password directly, with a centered confirmation; there is no separate unlink step. This removes the credential record and its Host associations together, then cleans up the unused Keychain secret after a successful metadata save. The confirmation lists affected Hosts if an older configuration shares the record. A secret still referenced by another credential or Project Web Link is retained. These actions change only the locally saved credential, not the server's password. Credentials also supports `e` to edit and `d` to delete.

Select a Host and press `k` to configure its SSH key. Enter sets that key's private path as the Host's `IdentityFile` in OpenSSH config, then installs its matching public key in the remote `~/.ssh/authorized_keys`; the private key never leaves the local machine. This pairs both sides of key authentication in one action. A trusted remote host key is required. Installation uses the Host's configured username and existing key/agent or saved Keychain password. If a password is needed or rejected, the same masked dialog used for Host connections asks for a replacement and whether to save it in the system Keychain. An upload failure explicitly reports that IdentityFile is already saved; select the same key again to retry. A local config write failure keeps the selector open and does not start an upload. Key assignment updates only `IdentityFile` in that alias's source SSH config block, preserving other options and creating a backup. Shared multi-alias or ambiguous blocks require manual editing. `User` remains defined by OpenSSH config. Removed aliases lose their password references after successful reconciliation, while saved credential records remain available in Credentials.

The Host key selector also retains `u` as a secondary upload-only action, without changing IdentityFile; the Hosts list has a single `k` entry point. A confirmation identifies the Host and `~/.ssh/authorized_keys`. Upload uses the alias's OpenSSH configuration, requires a trusted host key, creates private `.ssh`/`authorized_keys` permissions, preserves existing keys, and skips a public key already present with the same type and key material. Only public key material is sent. Upload can authenticate with the existing agent/key or an already configured saved password. Host connections first try available key/agent authentication and a saved Keychain password; when a password is needed or a saved password is rejected, LazyTerm prompts for a masked replacement and asks whether to save it. Host passwords are stored only in the system Keychain, with references in metadata. Native SSH and native SFTP use configured saved passwords through a scoped askpass helper, which retrieves the secret from the OS store and only answers the resolved target's exact password prompt. Passwords are never placed in arguments or environment variables. Jump-host passwords, interactive challenge-response, encrypted-key passphrase storage, and saved-password integration with embedded SFTP/Tunnels/remote Projects remain pending; imported encrypted keys can use normal OpenSSH/agent authentication.

Search captures typed characters, including digits, rather than switching tabs; `Ctrl+Left` / `Ctrl+Right` can still switch from search without clearing the filter. Add/edit and tag dialogs keep keyboard focus until saved or cancelled; `Tab` moves between form fields there. Use the visible number keys to jump tabs outside text input.

In Hosts, use `↑`/`↓` to select, `Enter` to open a group or connect to a host, `/` to search, `r` to reload, `f` for Files, or `t` for Tunnels. `a` and `e` open matching Host forms with fields in the order Alias, HostName, Groups, User, Port, and IdentityFile. Focus Groups and press Space to open its multi-select picker; filter existing groups and press Space to toggle them. Type a new group name, move to its create row, and press Enter to add it. Press Enter with an empty filter to apply selections and return to the form. New Hosts inherit the current group, and editing shows existing groups preselected. In the group overview, `A` adds an empty group, `E` renames the selected group and updates its Host assignments, and `D` deletes the group and removes its assignments without deleting Hosts. These empty groups are retained in LazyTerm metadata. Files always shows the local directory on the left. Its breadcrumb path is shown above the local list; click any visible path segment to jump directly to that directory, and LazyTerm remembers the last local path. Focus either pane and press `/` to filter its files and directories by name, `Enter` to keep the filter, or `Esc` to clear it. Hidden files and directories are hidden by default; press `h` in either pane to toggle them for both local and remote listings. The remote pane starts empty; focus it with `Tab` and press `Enter` or `s` to open a picker containing Groups and Hosts. Enter a group to see its hosts, then Enter a host to load its last remote directory, or its home directory the first time. In either pane, `↑`/`↓` selects, `Enter` opens a directory, `Backspace` returns to the parent, and `Tab` switches panes. Press `n` to create a directory, `m` to rename an entry, and `x` to delete it after confirmation. With a local file or directory selected, press `u` to upload it to the current remote directory; with a remote file or directory selected, press `d` to download it to the current local directory. Transfers run sequentially; the `TRANSFERS` area shows queued, active, completed, cancelled, and failed tasks with a progress bar and percentage. Use `[` / `]` to select a task, `c` to cancel the selected task, `C` to cancel all active and queued transfers, `R` to retry a failed or cancelled task, and `K` to clear terminal history. Transfers support ordinary files and recursive directories; interrupted recursive transfers remove empty directories created by that transfer. Existing transfer targets require overwrite confirmation. Remote `r` reloads and `o` opens the native `sftp <alias>` client. The embedded browser reuses the SSH alias and OpenSSH routing/config, shows remote size, permissions, owner/group IDs, and readable modification time when available, and requires a known host key plus key/agent authentication. Use native `sftp` for interactive password authentication or first-time host-key confirmation. Press `q` to quit. These shortcuts navigate LazyTerm's workspace; they do not switch SSH sessions while OpenSSH owns the terminal.

Hosts uses the same 40% browser / 60% details split as Projects, with **Groups** cards above the **Hosts** list on the left. Each card shows its name and host count. Columns adapt to the browser width, with left-aligned cards capped at 24 terminal columns each. At most two rows are visible, with scrolling for additional groups. Terminals narrower than 70 columns show only the browser. Arrow keys follow the grid: `←`/`→` move within a card row and `↑`/`↓` move between rows. From the last group row, `↓` enters the host list; from the first host, `↑` returns to the last group. Movement stops at the edges rather than wrapping. Hosts without tags appear in **Untagged**. Select a group and press `Enter` to see its hosts. Press `←`, `Esc`, or `Backspace` inside a group to return to the previously selected group card. Press `v` to return directly to the overview.

Select a host and press `g` to edit its comma-separated tags, then `Enter` to save or `Esc` to cancel. Tags work for both managed and existing OpenSSH hosts. A host with multiple tags appears in every corresponding group. Search matches aliases, destinations, and tags, and stays within the current group. New hosts created inside a tag group inherit that tag.

Host rows use two lines on the left for alias and address, with colored authentication badges aligned on the right. `Password` means a Host password is linked to the system Keychain. `Key uploaded` appears only after LazyTerm records a successful public-key upload for that Host. `SSH key` appears after a successful connection preflight confirms OpenSSH authenticated using `publickey`; this observation is persisted in LazyTerm metadata. Local OpenSSH identity candidates and ssh-agent keys are shown in the selected Host's connection details, but do not imply that authentication succeeded. Upload records are local history and can become stale if `authorized_keys` is changed externally.

Tags are stored separately from SSH configuration in `~/Library/Application Support/lazyterm/hosts.json` on macOS, or `$XDG_DATA_HOME/lazyterm/hosts.json` (default `~/.local/share/lazyterm/hosts.json`) elsewhere. The legacy `view` property is retained for compatibility but does not switch between separate Groups and Hosts pages. Tag edits do not modify `~/.ssh/config`.

OpenSSH configuration (including discovered `Include` files) is the source of truth for which hosts exist. On startup and `r` refresh, LazyTerm removes metadata for aliases that no longer exist and saves the cleanup only when needed. A missing root config is treated as an empty catalog. Read or parse failures preserve metadata instead of treating hosts as deleted. An externally renamed alias is treated as deletion plus addition; renames made in LazyTerm preserve tags. If a group loses its last host, the view returns to the group list.

The host-management scope covers common connection fields: alias, hostname, username, port, and identity file. Host passwords are optional and are stored only in the system credential store; LazyTerm metadata keeps a reference so OpenSSH can use them through the scoped askpass helper. Advanced OpenSSH directives and complex configuration rules remain editable directly in `~/.ssh/config`.

In the Hosts view, use `a` to add a managed host, `e` to edit a LazyTerm-managed host, and `d` to delete one after confirmation. Existing unmanaged OpenSSH hosts remain read-only in LazyTerm. Press `Enter` to hand an SSH session to the system OpenSSH client.

Runtime shows TCP listeners on the local machine or on a selected Host. The top row has clickable `Local` and `Hosts` selectors followed by the current machine name; category tabs sit below it. Press `h` or `s` to open the Groups/Hosts picker, `l` to return to Local, and `r` to refresh the inspection. Each machine keeps its own category, selected listener, and list position for the current app session. Switching machines shows its cached list while a fresh inspection runs; termination is disabled until that inspection succeeds. Older requests cannot replace the current machine's results. `Enter` keeps the selected listener focused and its details visible. Categories and listener rows also support mouse selection.

Entries are classified as `APP`, `SYSTEM`, or `UNKNOWN`, with application listeners shown first. Select a listener and press `k` to confirm sending `TERM`, or `K` to open a separate confirmation for `KILL`, using its visible PID; both confirmations name the target machine and block machine switching until dismissed. Runtime also queries the full command line and working directory for the PID when the platform permits it, so an Agent-started `node`, `python`, or similar process can be traced back to its project directory and command. Runtime uses `lsof` when available and falls back to `ss`; process names, paths, working directories, and PIDs may be unavailable without sufficient permissions.

Runtime also marks launch origin separately from ownership: `CLI` (cyan) for terminal/shell ancestry, `AGENT` (gold) for recognized Agent ancestry, `DESKTOP` (gray-blue) for macOS app bundles, and `UNKNOWN` when no evidence is visible. CLI and Agent listeners appear first within the application category. The details pane shows the classification evidence. Mine still includes desktop applications owned by the same user; colors distinguish their origin. These are observations of the current parent chain, not a durable launch audit: detached or reparented processes can lose their origin.

Runtime categories are ordered `Mine`, `Apps`, `System`, `All`; use Left/Right to switch. `Mine` is selected by default and shows non-system listeners owned by the current local user or remote SSH account, determined by numeric UID. It includes potential Agent leftovers, but does not prove which tool launched a process. `Apps` includes application processes belonging to other users; `System` is a heuristic based on known service names and system paths. Unknown entries remain accessible in `All`. Inspect the working directory and command before terminating a process.

Commands launched from Projects have a green `PROJECT` origin in local Runtime, with the project and command names shown beside the listener. These appear first in Mine and Apps. Press `o` on a Project listener to open its command output. `k` explicitly confirms stopping the entire managed command group, rather than just one listening child. Entering Runtime refreshes the inspection; use `r` to refresh while staying there. Association uses the owned process group and current run identity, not matching directory names or remote PIDs.

Recognized externally started Project commands appear in cyan as `PROJECT / EXT`, with the same project/output link. Their confirmed stop targets the observed command and its descendants individually, preserving unrelated processes in a shared terminal process group.

## Projects

Press `6` / `F6` for Projects. Use `a` to add a project with a name and absolute base directory (`~/...` is accepted), `e` to edit, and `d` to delete after confirmation. Enter a project to see its groups and commands in one list. Groups are expanded by default, with their commands indented below; ungrouped commands follow the groups. On a group header, Space or Enter toggles expansion, Left collapses, and Right expands. Left on a grouped command focuses its header. Fold choices are remembered separately for each project during the current app session. `v` switches to a flat list of all commands and back without losing folds. `G` adds a group; `e/d` edit/remove the selected group or command. Removing a group preserves its commands as ungrouped. Empty groups are supported.

Each command has shell text, an optional working directory, an optional group, a Service/Task type, an optional target override, and an `On exit` policy. A new group name in the command form creates that group. Type, target, and exit policy fields use Left/Right or Space to choose values. Local directories are validated on save and before execution. New and legacy commands without a type default to Task; mark long-running commands as Service to include them in batch controls.

Projects also store named web links, such as a local preview, admin console, or documentation. Inside a project, `L` adds a link with a name and a complete HTTP/HTTPS URL. A default-expanded `Web links` group appears above command groups, with link names and URLs indented like commands. Enter/Space or Left/Right on its header fold/expand it; Left on a link returns to the header. Fold state is remembered per Project for the session. The flat view lists all links and commands without headers. Select a link and press Enter to open it in the local browser; `e/d` edit or delete it with the usual confirmation. Links and their header never participate in service batch controls. Browser requests run in the background and failures appear in the status line. URLs are stored literally, so a `localhost` link always refers to the machine running the browser, including for Projects targeting a Host.

Web links optionally store a username and password. Password storage defaults to the system credential store (macOS Keychain, Linux Secret Service, or Windows Credential Manager); the link form also offers `Config file (plaintext)` for low-sensitivity self-hosted services. That choice shows an explicit warning because the password is written to `hosts.json` and its backups. Password fields are always masked and never load the existing secret into the form: leave the field blank to keep it, type a replacement, choose the storage method, or choose `Yes` for `Remove saved password`. On a selected link, `u` copies its username and `p` copies its password from the selected storage. Password clipboard contents are cleared on a best-effort basis after 30 seconds or normal app exit, only if the clipboard still contains that password. Keychain operations run in the background and report errors without falling back to plaintext. Enter opens the URL; browser autofill is not implemented. Deleting a link or Project removes unused keychain credentials after metadata is saved; copying metadata to another machine does not transfer Keychain passwords.

Select a command and press `s` to start, `x` to stop, or `r` to restart. `A/X` start/stop only Services in the selected header's or command's group; the project overview, flat view, and ungrouped commands scope these actions to the whole project. Tasks always run individually. Enter on a command opens output without starting anything. Use Up/Down to scroll, Home/End for the beginning/live tail, `[` / `]` to switch visible commands, and Esc to return from output to the list or from the list to Projects. Switching tabs preserves running tasks and workspace selection. Runtime output links automatically expand the linked command's group. Stop managed commands before editing or deleting their definitions.

Projects default to Local execution. Commands can inherit the project's target or override it with Local or a Host from the existing catalog. App-scoped remote commands run through `ssh` with BatchMode, no TTY, a bounded connect timeout, and a quoted remote `cd` plus `exec sh -c` command; stdout and stderr use the same output view and logs as local commands. Persistent remote commands, interactive PTY, and remote process rediscovery remain deferred. Removing a Host preserves Project definitions and does not retarget their commands; a missing Host must be reselected or changed to Local in the form.

Projects also checks for externally started commands asynchronously every three seconds. Recognition requires the current user's process, the configured working directory, and a matching command; common npm argument rewriting is normalized and descendant listening ports are shown. Directory or port matches alone do not establish a running command, and ambiguous definitions are left unassociated. Missing process metadata or rewritten process ancestry can prevent recognition. Running here describes process presence, not application health.

Current status is separate from the last managed run: an externally running server can coexist with a previous `exit 1`. Start and start-all inspect again before launching and skip recognized running commands. Stopping or restarting external commands requires confirmation and fresh identity/directory checks. External stop sends TERM to the observed processes without automatic KILL escalation; a stop that times out cancels restart. A successful restart launches a new managed run. External commands are never stopped on LazyTerm exit, and their existing stdout/stderr cannot be captured; the output view identifies any retained logs as the last managed run.

Each run uses `sh -c` in its own process group, inherits LazyTerm's environment, and has no interactive stdin or PTY. Use foreground commands such as `npm run dev` or `cargo test`; commands that deliberately daemonize or escape their process group are outside this supervisor's lifecycle. Stop sends TERM to the group and escalates to KILL after two seconds. Restart waits for the previous group and output readers to finish.

`On exit` defaults to `Stop on exit`, preserving the behavior of older commands: exiting LazyTerm kills their remaining managed groups. Choose `Keep running` before starting a command to use an independent background runner. That command and its log capture continue after quitting LazyTerm or closing its terminal. Reopening LazyTerm restores the run's status, output, log paths, and Runtime association; stop/restart work through the same controls. Active background commands show `/ background`. Navigation and app startup never launch a command automatically. Stop a running command before editing its exit policy; the new policy applies on its next start.

Background run records live under `project-logs/persistent-<project-id>-<command-id>.json`, alongside the private raw logs. Each command retains its latest background run's status and output tail, including its exit result. A per-command lock prevents simultaneous runners; control requests authenticate the recorded run rather than signaling a saved PID. Status queries run in the background. An unreachable runner is reported as unavailable and remains reserved, so retrying Start cannot silently create another instance. Killing the independent runner itself or deleting its records while it is running requires manual recovery; there is no automatic relaunch after a crash, logout, or reboot. App-scoped runs are still not recoverable after forced termination of LazyTerm.

The output view shows a scrolling 256 KiB tail with terminal escape sequences removed and stderr marked. Complete raw stdout and stderr are saved separately for each run in `project-logs/` beside `hosts.json`; their paths appear in command details. Log files use mode `0600`, the log directory uses `0700`, and logs remain across restarts and definition deletion. There is no automatic log rotation yet. Project definitions are stored in the existing version-1 `hosts.json` as an additive `projects` field, using the same atomic writes and `hosts.config.lazyterm.bak` backup. Existing files load with an empty project list. Projects survive Host reconciliation and remain separate from Snippet templates.

## Direction

- Reuse OpenSSH for interactive sessions, host key verification, and ProxyJump.
- Keep Host passwords in the operating system credential store; Project Web Links offer an explicitly labeled plaintext option for low-sensitivity services.
- Keep SSH sessions, the TUI, and tunnels on explicit, independent lifecycles.
- Build SFTP and tunnel management around shared host and credential models.
- Defer embedded terminal rendering, sync, and team features.

See [docs/architecture.md](docs/architecture.md) for the initial architecture and milestones.
See [ROADMAP.md](ROADMAP.md) for planned releases and [CONTRIBUTING.md](CONTRIBUTING.md) for the contribution workflow.

The v0.1.0 release gate is not yet met. See the roadmap audit for remaining favorites, SSH acceptance testing, and configuration-safety work; Files, Tunnels, and Snippets are not part of this milestone.

## Development

```sh
cargo fmt --check
cargo test
cargo clippy --all-targets --all-features -- -D warnings
```

The real SSH/SFTP fixture test is opt-in and requires `sshd`, `ssh-keygen`, and `ssh-keyscan`:

```sh
LAZYTERM_SFTP_FIXTURE=1 cargo test sftp_fixture_end_to_end -- --nocapture
```

It starts a temporary local `sshd`, uses temporary keys and configuration, tests the embedded SFTP operations, and removes the fixture when the test exits.

Normal `cargo test` also runs disposable Project process tests, including a temporary listener on an OS-assigned loopback port, concurrent commands, full output logs, TERM/KILL cleanup, restart, and the Projects -> Runtime -> output -> confirmed stop flow. These require local `ps` and `lsof` (or `ss`) and use no personal SSH configuration. The ignored `disposable_listener` test is a subprocess helper launched by these tests, not an untested acceptance gate.

External Project tests cover command/directory matching, ambiguous definitions, stale scan rejection, duplicate-start prevention, current status versus previous exit status, Runtime links, canceled stops, confirmed restart into managed execution, and preserving unrelated shared-group processes.
