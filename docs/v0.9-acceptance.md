# v0.9 Stable Core Acceptance

Status: development started on 2026-11-14, branch `v0.9-stable-core`.
This checklist records evidence and remaining gates; it does not declare a
stable release. v0.7 configuration sync remains paused.

## Automated Baseline

Run on a clean candidate with isolated disposable fixtures:

```sh
cargo fmt --check
LAZYTERM_SFTP_FIXTURE=1 cargo test --locked -- --test-threads=1
cargo clippy --locked --all-targets --all-features -- -D warnings
python3 -m unittest discover -s tests -p 'test_release.py'
```

On 2026-11-15, local isolated tests additionally verified schema-2 migration,
repeat import, stale-import refusal, backup recovery of Projects/groups/commands/
Web Links, UUID-first merge with colliding names, and private file permissions.
No real user profile was read or modified. The macOS CI and release workflows
enable the real SSH/SFTP fixture explicitly.
The release workflow also runs the separate password/ProxyJump/recovery fixture
with its pinned test-only Python environment. Confirm those steps actually pass
on both native CPU architectures; a test's opt-in early return is not evidence
of a successful transport test.

## Explicit Exclusions

- v0.7 sync remains experimental and unaccepted: encrypted sync, interruption
  recovery/history, missing-key handling and two-device acceptance remain open.
- Full localization, Host favorites and complete OpenSSH grammar are deferred.
  Ambiguous/shared Host writes are refused; manual configuration remains available.
- Background first-use Host-key approval, challenge-response and encrypted-key
  passphrase storage are unsupported. Pre-trust keys with OpenSSH.
- CLI configuration deletion/alias rename, generic Host/SFTP execution, arbitrary
  PID kill and remote external-process management are not Agent endpoints.
- Remote CLI Projects require keys/agent, trusted Host keys and Python 3/sh/ps;
  connection loss cleans their group. They are not detached remote services.
- Detached Tunnel rediscovery, remote detached-runner rediscovery and deliberately
  daemonized process cleanup remain outside the supervisor guarantee.
- Windows is unsupported; Linux is experimental. Public assets/tap and Developer
  ID/notarization need release infrastructure and maintainer decisions.
