# v1.0 Cross-Platform Acceptance

Development branch: `v1.0-cross-platform`. This document records evidence, not
an announcement of Linux or Windows support.

## macOS Lifecycle Baseline - 2026-11-16

The initial baseline had three intermittent failures: Project start preflight,
group Service start, and persistent-runner recovery after TUI SIGKILL. All
three passed individually and in one unchanged full run, but repeating the
runner case reproduced a real defect:

- A control client can disappear before the runner accepts its connection.
  On macOS, setting a timeout on that disconnected socket can return EINVAL.
  Propagating that client error ended the runner and cleaned its managed group.
- The runner now discards a client whose socket cannot be configured, leaving
  the service and other clients alive. A regression test disconnects 32 clients,
  then verifies authenticated status, listener availability, and stop.
  The test failed with the old implementation.
- Local process inspection previously used unbounded `Command::output`.
  Shared bounded collection now limits individual `ps`, listener and working
  directory queries to five seconds and limits each output stream to 16 MiB.
  Queries run directly, without a shell wrapper. Timeout/overflow kills and
  reaps the inspection child; Project preflight reports the error and cancels
  the action rather than treating it as an empty process snapshot.
- Tests cover a blocked query, large stdout/stderr, nonzero exit, overflow,
  and monitor recovery after a failed inspection. The precise cause of the
  earlier two start-preflight timeouts was not captured; successful reruns
  alone are not proof of their cause.

Validation on the uncommitted macOS working tree:

- `LAZYTERM_SFTP_FIXTURE=1 cargo test --locked -- --test-threads=1`:
  296 unit/App tests and 9 CLI tests passed; 8 unit subprocess/native-store
  helpers and 1 CLI helper were ignored. The three original failures and real
  SSH/SFTP fixture passed. The separate password fixture was not enabled.
- Persistent TUI/runner SIGKILL recovery passed 12 consecutive invocations.
- Formatting, Clippy with all targets/features and warnings denied, and
  `git diff --check` passed.
- These results do not establish native Linux or Windows acceptance.

## Platform Gates

### Linux Credentials and Native Baseline - 2026-11-16

- Native environment: Debian 12 ARM64 container, Rust 1.92.0, non-root user.
  The first Ubuntu 24.04 x86_64 CI run stopped before testing because the
  file-dialog dependency required Wayland development libraries. CI now
  explicitly installs those libraries and the process/SSH/credential fixture
  tools. The corrected hosted run passed; see the evidence below.
- Fixed `ttyname_r`'s buffer to use `libc::c_char`, whose signedness differs
  between macOS and Linux ARM64. No macOS backend, credential service name,
  reference format, or existing password error wording was changed.
- Linux continues to use the existing `keyring` Secret Service backend, with
  encrypted D-Bus secret transport enabled. Linux-only error descriptions cover
  unavailable/failed services, denied/locked storage, missing passwords and
  ambiguous entries. Raw backend details are not rendered, and no plaintext
  Host-password fallback is introduced.
- `LAZYTERM_SFTP_FIXTURE=1 cargo test --locked -- --test-threads=1`:
  297 unit/App tests and 9 CLI tests passed, including the real SSH/SFTP fixture
  and Project/Runtime lifecycle tests. Twelve unit tests/helpers and one CLI
  helper were ignored; the separate password SSH fixture was not enabled.
- `bash scripts/test-linux-credentials.sh` passed against a real GNOME
  Secret Service: unavailable session bus; create/read/update for both Host
  credential and Project-link namespaces; fresh-process reads; delete and
  repeated delete; locked-keyring read/update/delete failures without a
  graphical prompter. The fixture has a temporary home and private session bus
  and never uses the macOS Keychain or an existing user collection.
- Linux-specific error-mapping tests verify that raw backend details are not
  disclosed. `--diagnostics` identifies the Linux backend without probing
  credentials or collecting session environment values.
- macOS regression: 296 unit/App tests and 9 CLI tests passed with the real
  SSH/SFTP fixture enabled; 8 unit helpers and one CLI helper were ignored.
  The opt-in native macOS Keychain test was not run, so these checks did not
  access the user's saved passwords. Formatting and all-target/all-feature
  Clippy with warnings denied passed on both macOS and Linux ARM64.
- The PTY CLI test uses an explicit raw pointer for `openpty`'s window-size
  input to accommodate the Linux/macOS signature difference; its behavior is
  unchanged.

### Ubuntu x86_64 CI and Graphical Credential Probes - 2026-11-16

Hosted [CI run 43825660012](https://github.com/humbertyu/lazyterm/actions/runs/43825660012)
passed both Ubuntu 24.04 x86_64 and macOS jobs at commit `03b53b4`.
Ubuntu passed formatting, unit/App and CLI tests with real SSH/SFTP enabled,
the isolated GNOME Secret Service fixture, and all-target/all-feature Clippy
with warnings denied. macOS passed its corresponding regression suite.
An earlier CI-only large-output test failure was fixed by giving that test
its own 30-second allowance. The production five-second timeout is unchanged.

Additional graphical probes used Debian 12 ARM64, Xvfb 21.1.7 and Openbox
3.6.1, with separate temporary homes and private session buses:

| Provider | Version | Observed result |
| --- | --- | --- |
| GNOME Keyring / GCR | 42.1 / 3.41.1 | Save password, lock, inspect actual unlock dialog, enter wallet password and read in a fresh process: passed. |
| GNOME Keyring / GCR | 42.1 / 3.41.1 | Cancel unlock: sanitized error. Retry, unlock and read original password: passed. Delete and confirm absence: passed. |
| KWallet | Frameworks 5.103.0 | Create password-protected `kdewallet` through Wallet Manager, save and read via Secret Service: passed. |
| KWallet | Frameworks 5.103.0 | Lock, inspect actual password dialog, unlock/read, cancel, retry/unlock/read, delete and confirm absence: passed. |

The ignored `linux_secret_service_desktop_probe` test drives the application's
`SystemStore` methods. `LAZYTERM_SECRET_SERVICE_FIXTURE=desktop` and
`LAZYTERM_DESKTOP_PROBE=seed/read/cancel/delete` select the operation.
Dialogs were visually inspected and operated during this run. Only disposable
passwords were used; neither user configuration nor the macOS Keychain was
accessed. Providers had independent homes and session buses.

A fresh KWallet without an initialized collection initially rejected storage;
creating the encrypted default wallet in Wallet Manager resolved it. LazyTerm
does not initialize an empty-password wallet. Cancel did not delete or replace
the original credential on either provider.

These are graphical credential-provider probes, not full GNOME Shell/Plasma
manual acceptance. Real desktop TUI save/login/update/delete, focus return,
PAM login unlock, Wayland/session restart, and install/upgrade/uninstall checks
remain pending. This evidence must not be labeled complete human desktop
acceptance.
