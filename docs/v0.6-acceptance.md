# v0.6 Beta Acceptance

Run automated checks first:

```sh
cargo fmt --check
cargo test --locked
cargo clippy --locked --all-targets --all-features -- -D warnings
```

Manual checks should use a disposable SSH account or VM. Do not test password replacement, key upload, remote process termination, or tunnel recovery against a production host.

## Settings and Languages

- Press `,` from each workspace and verify Settings opens without changing the selected workspace when dismissed.
- Change Language from English to 中文, then 日本語, then English. Verify the choice survives restarting LazyTerm.
- Verify Settings, top navigation, and the translated page headings/empty states change. Record any remaining English labels; complete localization is still in progress.
- Change theme and tab visibility, restart, and confirm both settings persist and Settings remains reachable.

## Configuration and Credentials Import/Export

- Import a package with a same-alias Host and a new Host. Verify the imported alias wins without per-conflict prompts, including when the old alias lives in a different Include file; verify local-only Hosts remain. Check advanced directives/comments in the incoming stanza and shared multi-alias local blocks.
- Repeat the import and verify no duplicate entries appear. Test identical UUIDs after renaming a Project/command, UUID conflicts, independently created same-name records that use different UUIDs, local-only commands, and preserved local Web Link passwords. Archive omissions must not delete local entries. Verify v2 numeric IDs migrate to UUIDs and Host password/Web Link references still resolve.
- In Settings, run Export configuration and choose a destination. Inspect the JSON and verify it includes `hosts`, `ssh_config`, `ssh_config_files`, groups/tags, tunnels, snippet packages, projects, web links, and credential references.
- Verify the configuration export has `passwords_included: false`, contains no saved Host or Project Web Link password, and is created with owner-only permissions on Unix.
- Run Export credentials, enter matching export passwords, and choose a destination. Verify the resulting `.age` file is non-empty and private; verify a wrong password does not decrypt and the matching password does.
- On a disposable profile, import the configuration JSON. Verify the confirmation reports the Host count, the host aliases and SSH Include files are restored under the current `~/.ssh`, and metadata entries are restored. Verify the pre-import files are present in `import-backups/` and `hosts.json.backups/`.
- Import the `.age` file, first enter a wrong password and verify no changes occur, then use the correct password and confirm. Verify Host/managed Keychain credentials and Project Web Link passwords are restored. If a Keychain reference already exists, verify the new value replaces it and an age-encrypted pre-import backup is created.
- Test malformed JSON, unsupported versions, a config path outside the archived `.ssh` directory, and a configuration archive containing plaintext Project passwords. Each must be rejected before changing files.
- Verify an SSH config write failure restores previously replaced config files. Do this only with a disposable profile.

## Host Credentials and SSH

- Connect to a disposable password-only Host without a saved password. Verify the dialog asks for both username and password, masks input, and offers an explicit Keychain-save choice.
- Repeat with a saved password, then change the server password. Verify a rejected saved password opens the same prompt, retry succeeds, and choosing save replaces the existing local Keychain credential.
- Verify `x` removes the local saved password but does not alter the server account.
- Test public-key generation, assignment, upload, reconnect, and removal from `authorized_keys` on the disposable account. Confirm the private key stays local and the Host gets `IdentityFile`.
- Verify Host-key first-use confirmation and changed-key rejection.

## Connected Workflows

- Use native SFTP (`r` in Files) with a saved password and verify it authenticates. The embedded SFTP browser currently requires a key or agent and cannot consume a saved password.
- Start a Tunnel, a Snippet, and an app-scoped remote Project command against the disposable Host with an existing saved password. Verify each starts and its status/output is visible.
- Without a saved password, verify unsupported workflows fail with a clear message. First-use password prompts for Tunnel, Snippet, and Project are not implemented yet.
- Exercise transfer, cancellation, retry, rename, delete, tunnel stop, and project stop against disposable data/processes.

## Recovery and Release

- Start a Project service and verify normal close/reopen restores a persistent runner. Force-kill only a disposable runner/TUI and confirm no duplicate process starts and Runtime reports remaining processes.
- Force-kill a disposable Tunnel and record whether the next launch recovers or reports it; forced-TUI Tunnel rediscovery is not implemented yet.
- Native macOS x86_64 and arm64 release builds, signed distribution, and published checksums remain release tasks.
